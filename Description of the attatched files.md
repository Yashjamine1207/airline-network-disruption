#### **Airline development roadmap**

Covers the complete 10–12 week analytical path: data acquisition, timestamp/timezone reconstruction, regime-shift analysis, delay/cancellation targets, leakage-safe features, baselines, boosting, aircraft rotations, propagation, network science, survival/recovery, weather event analysis, TensorFlow LSTM/GRU/Transformer ablations, calibration, error analysis, prioritisation, and final reports.



#### **Airline repository structure**

Provides the complete airline-network-disruption-intelligence directory tree, including dedicated modules for timestamps, aircraft rotations, weather matching, dynamic network construction, survival analysis, evaluation, explainability, configurations, documentation, tests, reports, and optional read-only presentation.



#### **Important GitHub files**

Defines exactly which root files, documentation, configuration files, and optional assets to create. It also defines the required README structure, dependency strategy, and the production-style files/folders that must not be added.

Protects the Kaggle flight data, NOAA weather extracts, Parquet outputs, DuckDB files, model artefacts, TensorFlow checkpoints, MLflow runs, local credentials, environment files, and generated development outputs.

Defines all non-negotiable rules for data handling, time zones, prediction timestamps, leakage prevention, targets, temporal validation, model comparisons, calibration, network analysis, survival modelling, explainability, operational-value scenarios, testing, GitHub safety, and scope control.
